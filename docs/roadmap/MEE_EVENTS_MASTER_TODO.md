## Priority meaning

- **P0 — Critical:** Current security, integrity, build, or governance risk. Release blocker.
- **P1 — Blocking:** Required for the next product or production gate.
- **P2 — Important:** Required business workflow and operational completeness.
- **P3 — Feature completion:** Required to finish the promised product surface.
- **P4 — Polish:** Accessibility, performance, content, UX and operational refinement after core correctness.

## How every line becomes an execution block

Every checklist line below is a complete execution block and carries these fields:

- **TASK ID / TASK NAME:** the checkbox label.
- **OBJECTIVE / WHY:** `Objective` field.
- **CURRENT STATE:** one of DONE/PARTIAL/BROKEN/MISSING/BLOCKED/NOT VERIFIED in `State`.
- **EXPECTED RESULT / RESULT / DEFINITION OF DONE:** `DoD` field; the result remains pending until evidence is recorded.
- **SCOPE / FILES TO INSPECT / FILES EXPECTED TO CHANGE / IMPLEMENTATION:** `Scope` and `Action` fields. Inspect first; change only the smallest confirmed set.
- **OUT OF SCOPE:** the next task, next module, opportunistic refactors, provider procurement, deletion, and architecture changes unless the row explicitly includes them.
- **DEPENDENCIES / RISK:** `Depends/Risk` field.
- **TESTS / SECURITY / VERIFICATION:** `Test/Security` and `DoD` fields.
- **DOCUMENTATION:** update this file only if scope/status changes; always update `MEE_EVENTS_PROGRESS.md` and evidence links.
- **COMMIT:** one scoped commit only after all gates pass; no unrelated files.
- **NEXT TASK:** the explicitly named `Next` value. Stop after closing the current block.

Status marks in this file describe execution, not how much scaffold already exists:

```text
[ ] Not started   [~] In progress   [x] Completed   [!] Blocked   [✗] Failed
```
